# 私有 GitHub 数据仓库衔接插件与后台任务

完整收藏数据持久保存在用户的私有 GitHub 仓库，插件保留本地缓存并支持离线收藏，联网后同步，GitHub Actions 从仓库读取数据执行周期任务。公开网站仅接收用户选择发布的内容。

选择这一路径是为了复用现有 GitHub 使用方式、支持浏览器关闭后的处理，并减少单独维护服务端的负担；代价是同步存在延迟，而且 GitHub 文件写入不提供收藏条目级的自动合并。插件和后台任务的并发修改、尚未同步的本机数据、令牌配置及备份规则需要明确设计。

首版支持同一人在多个 Chrome 实例编辑。不同字段的修改可以自动合并，同一字段的两份人工修改保留双方内容并提示用户选择。首版接受手动配置限定数据仓库的 GitHub 令牌，并可在本机记住以便重启后同步；提供仅本次会话保存的选项。令牌不进入收藏数据或页面脚本，模型密钥放在 Actions 或 CLI 的运行环境中。

用户要求插件内一键触发云端 Actions。因此插件令牌除数据仓库 Contents 读写外，还需该仓库的 Actions 写权限，并显示任务与同步状态。触发前应先同步相关数据；同步失败时不把旧数据的执行显示成该次操作已完成。该权限范围不止触发工作流，初始化说明必须写清楚；插件仍不直接启动本机 Codex。
