# 链接状态独立展示与周期复查

普通网页和 GitHub 项目可能失效、暂时不可访问或转为受限。用户明确要求失效单独标记，收藏不因此删除或自动取消公开；公开网站默认仍显示已选中的失效条目，提供“隐藏失效收藏”筛选。

Q45、Q46 接受四种状态：未检查、可访问、检查受阻／待复查、持续不可访问。最近检查时间、简短原因与最后一次成功信息一并保留；这些状态反映检查观测，不声称能证明资源永久删除。

至少两次有效检查得到 404/410，且间隔至少 24 小时，才自动标为持续不可访问。GitHub 404 同样记录，但必须说明无法区分删除、私有化或权限变化。登录限制、限流、超时、服务器错误及 DNS/TLS 失败先作为检查受阻；归档、禁用、可见性和长期不更新分别表示，不等同于失效。2xx 只表明检查请求成功，不保证页面仍包含原内容；明显登录页或疑似错误页保留无法确认的说明，不依靠 AI 猜测删除。

用户可以人工标记或解除失效，人工判断优先并保留到明确解除。自动观测仍可更新并显示，不覆盖人工选择；解除人工覆盖后使用最近有效的自动状态。自动确认恢复可清除自动失效状态，但不修改公开规则或复活回收站条目。

任务每天检查到期项；普通链接正常和失效状态默认均每 7 天复查，首次 404/410 至少 24 小时后安排复核。每轮普通网址最多 500 个，频率和上限可配置，并支持立即复查。GitHub 仓库主页复用按仓库去重的元信息请求，具体文件等深层网址不能因仓库仍存在就判为可访问，需单独检查。已有 GitHub 元信息的每日检查、7 天新鲜度和每轮 500 仓库限制继续有效。

重定向可跟随以观测最终响应，同时记录目标并提示用户；不自动改写收藏网址或合并条目。HEAD 不支持或结果不可靠时使用受限 GET 复核；设置请求超时、响应读取上限、重定向上限和按站点限速。云端检查不携带浏览器 Cookie，不访问本机或私有网络地址，不要求部署登录浏览器或通用爬虫。完整 URL 的片段仍参与收藏身份，HTTP 检查并不验证页面内片段或脚本状态。

失效时保留已有标题、标签、用户备注和最后一次成功获取的元信息，不用空响应覆盖。公开输出增加有效链接状态、简短原因及最近检查时间；不发布原始响应、认证诊断或私有元信息。隐藏失效收藏仅影响访客视图，不改变公开清单。

HTTP 404 不能证明永久删除，410 表达服务端认为资源可能永久不可用；GitHub 对未授权私有资源也会返回 404。归档表示只读且可恢复。复查阈值和周期是本产品选择，不是这些协议的规定。[HTTP 语义](https://www.rfc-editor.org/rfc/rfc9110.html#name-status-codes)、[GitHub 404](https://docs.github.com/en/rest/using-the-rest-api/troubleshooting-the-rest-api#404-not-found-for-an-existing-resource)、[归档](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories)、[返回 200 的错误页](https://developers.google.com/search/docs/crawling-indexing/troubleshoot-crawling-errors#soft-404-errors)
