# 私有数据仓库与公开 Pages 承载仓库

个人实例由私有数据仓库和公开 Pages 承载仓库组成，产品代码仍集中在 monorepo。用户在 Q38 明确选择 Actions 临时产物部署 Pages，收藏数据不提交到公开 Git；公开仓库可以保存工作流及站点配置。持续 amend 曾被考虑，但它只能压平可见历史，不能保证旧 SHA 对象不可访问，因此没有采用。

这保留 GitHub Free 兼容，但需要两个实例仓库和显式交接：私有工作流导出白名单数据为私有 artifact，再触发公开发布工作流；后者下载指定导出，与网站文件组合，在本次公开 run 上传 Pages artifact 并部署。浏览器直接读取 Pages 托管的数据文件，Artifact 只是发布中转，不是 Release 附件或网页的数据下载 API。

跨仓库交接分别需要对公开仓库的 Actions:write 和对私有源仓库的 Actions:read；公开任务无需读取私有仓库 Contents。Pages 部署使用当前公开仓库 GITHUB_TOKEN 的 pages:write、id-token:write，产物清理需要 actions:write。权限仍是仓库级，不能宣传为只允许一个 workflow 或单个 artifact。

处理、公开导出和发布要显式衔接，不依赖 GITHUB_TOKEN 自动提交触发下一段 on:push 工作流。公开站点更新后，插件和站点应能显示各自数据版本，避免把私有同步成功误报为公开发布已经成功。

发布始终只包含字段白名单内的输出，私有原始数据、用户备注、处理记录和密钥不得进入公开产物。部署成功后清理公开 artifact，以短保留期处理清理未完成的情况，日志及 summary 不打印收藏内容。必须验收“部署成功、删除临时产物后，站点和数据仍可访问”，以及失败和取消时的清理。

本决策避免数据进入公开 Git，不承诺 GitHub 后台缓存或第三方副本的彻底擦除；临时公开 artifact 在删除前可被具备读取权限的登录用户下载。取消公开仍通过下一次成功部署更新当前站点。
