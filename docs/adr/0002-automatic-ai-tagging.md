# AI 打标签与新标签定义自动生效

AI 为收藏分配标签、创建新标签及其定义时，结果允许自动生效，用户事后修订。相比逐条确认，选择较低的日常操作负担，并接受标签体系需要事后纠正和整理的代价。

人工修订按每条收藏的每个标签关联、每个被编辑字段分别保护。用户明确拒绝或删除的标签不能被下一轮 AI 自动补回，手工添加的标签也不能由 AI 删除；其他未保护的标签仍可自动更新。普通重跑保留全部保护，只有明确选择“解除所选保护并重算”才解除相应范围，避免为了修正一个标签而冻结整条收藏。

自动归类优先复用已有标签，确实需要时可自动新增标签及定义。已有标签的改名、合并、删除和适用边界变更由用户操作；AI 可补缺失信息，译文按既定策略更新。上述自动更新权不包含擅自改变已有标签体系的含义。证据不足的收藏保留为待处理并说明原因，不强行归类。

无人值守任务主要通过用户自行配置的模型 API 执行，同一套任务提供 CLI 手动入口，agent 可通过 skill 调用。统一、可版本管理的政策必须覆盖所有产品内 AI 编写或生成的内容：收藏分类、标签命名、新定义编写、打标规则编写、标签显示名和定义翻译，以及实际输出的说明文字。skill 包含或明确引用这套完整政策，API 任务使用同一来源的政策，结果经过程序校验；不能只规范分类，也不能把 skill 文本本身当成执行保证。

周期任务默认增量处理：新收藏、待重试项、缺失定义和译文进入处理范围；已有 AI 结果仅在相关内容或规则改变、或用户主动要求重新整理时重新生成。GitHub 元信息按各仓库的到期时间刷新，各任务的频率和批量预算分别配置，人工修订保护始终有效。

初始默认值为：AI 分类及缺失定义/译文每 6 小时处理；GitHub 元信息每天检查，每仓库 7 天过期，每轮最多处理 500 个仓库，额度不足时提前停止，下次继续。频率、新鲜度与单轮上限均可配置，CLI 可手动触发。长期 AI 批量、模型和月费用上限在以下调试范围验证后确定。

本机调试已选择由 Rust CLI 启动 codex exec；HTTP 路径使用 DeepSeek 官方 deepseek-flash，以 20 条样本对照，总调试预算 2 元且包含重试。长期自动任务的模型与月预算待样本结果确定；GitHub-hosted Actions 不会自动获得访问用户 PC 上 Codex 的通路。

任务失败与规则变化后的重算不得隐式解除人工保护；多设备对同一内容的人工冲突仍由用户处理。API 失败分类、最多三次尝试、认证或余额问题后的挂起与手动恢复，以及私有故障 Issue 通知已在 [ADR 0014](0014-api-failure-recovery-notifications.md) 确定。完整 AI 政策目录见[执行工作流](../execution-workflow.md)。
