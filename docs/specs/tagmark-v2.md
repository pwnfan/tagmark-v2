# TagMark V2 — 开发规范

日期：2026-10-23。

状态：产品范围及本文四组测试边界均已获用户确认。本文按 to-spec 汇总既有决定，已发布为 [Spec #1](https://github.com/pwnfan/tagmark-v2/issues/1) 并标记 ready-for-agent。项目技能配置已获确认并写入；当前进入 to-tickets 拆分审阅，尚未开始产品实现。

## Problem Statement

个人收藏目前分散在录入工具、Python 处理程序和只读网站中。用户希望收藏时不必手工组织标签，之后仍能检查和纠正分类；现有标签说明、程序更新和网站部署不足以构成可持续的自动整理流程。

完整收藏库包含私人内容，用户又需要分享其中一部分。公开选择必须可解释，明确不公开的标签必须阻止条目发布；同步成功也不能被误认为公开网站已经更新。多设备、离线修改和后台 AI 可能同时处理同一内容，不能造成用户判断被覆盖或已删除收藏重新出现。

此外，网页与 GitHub 项目会迁移、失效或转为受限；模型 API 会限流、故障或耗尽余额。用户需要看到可信的状态、保留已有成果并收到可处理的故障通知，而不是依靠反复检查日志维护整个系统。

## Solution

提供单人自部署的 TagMark V2：桌面 Chrome 插件承担收藏、编辑和离线管理，个人私有 GitHub 数据仓库保存完整状态，Rust CLI 在本机或 GitHub Actions 中执行增量整理、元信息刷新、链接复查及公开导出，独立网站提供公开内容的双语浏览和分享。

AI 可以自动分配标签并新增必要标签及定义，所有生成任务使用同一套政策；用户的人工修订受程序保护。公开范围由标签规则和逐条选择共同形成，不公开标签具有一票否决权。公开网站只取得允许的条目和字段，收藏数据经临时部署产物进入 Pages，不提交到公开 Git 历史。

## User Stories

### 安装与个人实例

1. 作为个人收藏库维护者，我希望从空实例开始使用 V2，从而无需先迁移旧版数据。
2. 作为自部署用户，我希望产品代码与个人数据分离，从而升级工具时保留自己的收藏、部署设置和凭据边界。
3. 作为 Windows、Linux／WSL 或 macOS 用户，我希望下载对应平台的 CLI 后直接运行，从而无需安装 Rust 或其他语言运行时。
4. 作为 Chrome 用户，我希望加载可下载的插件包并按说明完成配置，从而在首版尚未上架商店时也能使用。
5. 作为维护者，我希望手动配置限定仓库的 GitHub 凭据，并选择本机记住或仅会话保存，从而控制同步权限与凭据保留方式。
6. 作为维护者，我希望安装说明区分数据访问、Actions 触发、跨仓库发布和通知权限，从而按实际用途完成配置。

### 收藏与网址身份

7. 作为用户，我希望在当前 Chrome 页面主动保存 HTTP(S) 网址，从而替代原有工具的日常收藏入口。
8. 作为用户，我希望收藏时先保存网址及允许采集的页面信息，从而不必当场手工输入标签。
9. 作为用户，我希望离线时仍能录入和编辑，从而在恢复联网后继续同步。
10. 作为用户，我希望同址重复收藏进入原条目并保留人工修改，从而避免重复记录和已有整理丢失。
11. 作为用户，我希望 HTTP/HTTPS、不同片段、查询参数顺序和有意义的路径差异保留区别，从而不同页面状态可以分别收藏。
12. 作为用户，我希望标题或网址编辑不改变收藏身份，网址发生冲突时提示处理，从而不会静默合并两份人工内容。
13. 作为用户，我希望记录私人备注，从而保存不必公开或发给模型的个人判断。
14. 作为用户，我希望控制正文摘录是否用于 AI，并能对单条收藏跳过 AI，从而控制主动收藏内容的外发范围。

### 自动整理与完整 AI 政策

15. 作为用户，我希望 AI 按主要主题、用途和资源类型打标签，从而获得与收藏内容有关的分类。
16. 作为用户，我希望偶然使用的实现语言作为 GitHub 元信息供筛选，从而不把实现技术误当作收藏主题。
17. 作为用户，我希望 AI 优先复用已有标签，确有需要时自动新增标签和定义，从而减少同义概念重复与日常审批负担。
18. 作为用户，我希望证据不足时保留待处理原因，从而不被强行归类或虚构结论误导。
19. 作为用户，我希望标签具有稳定身份、英文标准名和简短英文定义，从而不同语言下仍表示同一概念。
20. 作为用户，我希望标签另有适用、排除和例子的打标规则，从而分类边界可以检查和维护。
21. 作为维护者，我希望 skill 和 API 共用完整、版本化的生成政策，从而分类、命名、定义、规则和翻译保持一致。
22. 作为维护者，我希望所有实际由 AI 编写的说明文字也受政策约束，从而新增生成内容不会绕开质量要求。
23. 作为用户，我希望模型只接收允许的标题、简介、正文摘录及公开 README，从而私人备注、历史、Cookie 和凭据不会混入提示词。
24. 作为用户，我希望网页与 README 中的指令只作为待处理内容，从而不能改变工具权限或发布决定。
25. 作为维护者，我希望程序验证结果结构、引用、允许写入范围和输入版本，从而模型输出不能直接覆盖整个收藏库。
26. 作为用户，我希望自动整理只处理新增、缺失、待重试或确需重算的内容，从而减少重复生成和费用。
27. 作为本机用户，我希望 CLI 调用 codex exec 完成 AI 任务，从而无需为本机调试维护常驻 HTTP 服务。
28. 作为云端用户，我希望同一任务能通过已配置的 HTTP 模型服务运行，从而不依赖自己的电脑保持开机。

### 人工修订、标签维护与双语

29. 作为用户，我希望手工添加的标签不被 AI 删除，从而保留我的分类判断。
30. 作为用户，我希望手工拒绝的标签不被 AI 加回，从而不用反复纠正同一错误。
31. 作为用户，我希望保护按标签关联和被编辑字段分别生效，从而修改一处不会冻结整条收藏的自动整理。
32. 作为用户，我希望普通重跑保留人工保护，并能明确解除所选保护后重算，从而控制重新自动处理的范围。
33. 作为用户，我希望手工改名、合并和删除标签，并保留适当别名，从而维护平面标签体系且不改变概念身份。
34. 作为用户，我希望已有标签的语义边界由我决定，从而 AI 不会擅自重新定义已有分类。
35. 作为用户，我希望插件和网站提供英文与简体中文界面，从而按自己的语言习惯操作。
36. 作为用户，我希望标签显示名和定义具有相应译文，从而阅读中文时仍能使用统一的英文概念体系。
37. 作为用户，我希望译名、别名和旧名都能检索到同一标签，从而不必记住唯一的标准拼写。
38. 作为用户，我希望原文变化后自动译文可更新、人工译文保留并提示复核，从而兼顾新鲜度与人工判断。
39. 作为用户，我希望缺失译文时回退英文，从而条目保持可读。

### 管理、检索与同步

40. 作为用户，我希望在插件独立管理页面编辑收藏、标签和定义，从而集中整理资料。
41. 作为用户，我希望进行中英文关键词和标签布尔检索，从而用 AND、OR、NOT 和括号组合查找内容。
42. 作为用户，我希望按 GitHub 语言、星标和归档状态筛选，从而比较项目而不混淆用户标签。
43. 作为用户，我希望批量调整标签、逐条公开选择和删除状态，从而高效处理多个收藏。
44. 作为用户，我希望本地缓存与私有 GitHub 数据同步，从而浏览器关闭后后台仍能处理已同步内容。
45. 作为多设备用户，我希望不同字段的独立修改自动合并，从而减少不必要的冲突处理。
46. 作为多设备用户，我希望同一内容的人工冲突保留双方并让我选择，从而不会静默丢失其中一份修改。
47. 作为用户，我希望较旧的 AI 结果不能覆盖较新的输入或人工决定，从而并发处理保持一致。
48. 作为用户，我希望分别看到未同步、同步冲突、已触发、运行中、失败及公开部署状态，从而知道操作实际完成到了哪一步。
49. 作为用户，我希望在插件中一键触发云端任务，并先同步相关修改，从而处理的是我刚才编辑的内容。
50. 作为用户，我希望 CLI、Actions 和插件入口执行同一套任务规则，从而不同入口不会产生不同数据语义。

### 公开清单与分享

51. 作为维护者，我希望完整收藏库默认私有，公开选择默认仅手动，从而新实例不会自动发布收藏。
52. 作为维护者，我希望按包含标签选出收藏，再扣除排除标签，从而分享指定主题。
53. 作为维护者，我希望主动切换为“全部减去排除标签”，从而也能按反选方式维护分享范围。
54. 作为维护者，我希望包含列表内匹配任意标签即可，空包含列表选中零条，从而规则保持可预测。
55. 作为维护者，我希望每条收藏可跟随规则、手动公开或手动私有，从而处理个别条目的分享需求。
56. 作为维护者，我希望任一明确不公开的标签都能否决发布，即使条目被手动设为公开，从而不会越过明确的隐私边界。
57. 作为维护者，我希望未设置公开性的标签保持中立，从而不必将每个标签都加入公开列表。
58. 作为维护者，我希望保存规则前看到最终清单、数量、增删变化及原因，从而理解实际公开范围。
59. 作为维护者，我希望启用标签规则后新增收藏和标签变化自动更新清单，从而无需逐条再次批准已选择的分享规则。
60. 作为维护者，我希望公开输出只含允许条目及字段，从而备注、正文、规则、AI 日志、冲突和回收站保持私有。
61. 作为访客，我希望不用登录就能浏览和检索公开收藏，并分享 V2 查询链接，从而直接使用个人分享网站。
62. 作为维护者，我希望取消公开在下一次成功部署后生效，并能看到尚未部署的变化，从而不把发布失败误认为撤回完成。
63. 作为维护者，我希望收藏数据不进入公开 Git 历史，从而公开仓库不会累计曾经发布的收藏快照。
64. 作为维护者，我希望部署只使用临时 Actions 产物并在部署后清理，从而完成 Pages 发布而不把数据放进 Release 或 Git 提交。
65. 作为访客，我希望网站直接读取 Pages 上的压缩数据，从而不必访问需要登录的产物下载接口。

### 链接与 GitHub 状态

66. 作为用户，我希望链接状态与删除和公开状态分开，从而失效收藏仍能保存和分享。
67. 作为用户，我希望区分未检查、可访问、检查受阻／待复查和持续不可访问，从而不把一次网络故障误认为永久删除。
68. 作为用户，我希望 404/410 经至少两次、间隔至少 24 小时的检查后才标为持续不可访问，从而降低误判。
69. 作为用户，我希望 GitHub 404 保留删除、私有化或权限变化的不确定性，归档、禁用和长期不更新另行显示，从而理解真实观测范围。
70. 作为用户，我希望正常及失效链接定期复查，也能立即复查，从而看到恢复后的状态。
71. 作为用户，我希望人工标记或解除失效后保留人工判断，从而自动检查不会覆盖我的决定。
72. 作为用户，我希望失效时保留标题、标签、备注和最后成功元信息，并记录检查时间与原因，从而仍能辨认收藏。
73. 作为用户，我希望重定向只提示目标，不自动改网址或合并，从而保留我收藏的完整 URL 身份。
74. 作为访客，我希望默认仍能看到公开的失效收藏，并可筛选隐藏它们，从而自行选择是否查看这些资料。

### 调度、故障、成本与恢复

75. 作为维护者，我希望任务频率、新鲜度和批量限制分别可配置，并在额度不足或中断后续跑，从而控制资源消耗。
76. 作为维护者，我希望 GitHub 元信息按仓库去重并直接读取 API，从而避免重复请求和模型猜测。
77. 作为维护者，我希望认证或余额故障立即停止并挂起自动 AI，修复后手动恢复，从而不会反复发起无效调用。
78. 作为维护者，我希望临时故障有限重试、合格结果保留且失败真实可见，从而能够恢复工作并避免残缺数据落库。
79. 作为维护者，我希望首次未恢复故障通过私有 Issue 提及本人，重复故障不反复提醒，恢复时关闭，从而及时处理且不过度打扰。
80. 作为维护者，我希望通知失败也可见，同时保留原始故障，从而不会误以为提醒已经送达。
81. 作为维护者，我希望 20 条代表性样本对照 Codex 与 DeepSeek Flash，所有 DeepSeek 尝试合计不超过本次 2 元预算，从而先验证质量与成本再决定长期设置。
82. 作为用户，我希望删除进入回收站、迟到的编辑不自动复活条目，并可单条恢复，从而保留可控的撤销路径。
83. 作为维护者，我希望整库备份包含完整 V2 状态但不包含密钥，并恢复到新空实例，从而能够验证恢复的一致性。
84. 作为使用发行包的用户，我希望安装、配置、限制和实际验证平台都写清楚，从而区分已经验证的能力与仍需环境验证的部分。

## Implementation Decisions

1. **部署与职责。** 产品为单人自部署工具，无共享账号服务。产品代码采用一个 monorepo，完整个人数据与部署设置放独立私有实例仓库，另有兼容 GitHub Free 的公开 Pages 承载仓库。插件编辑，网站只读。
2. **技术选择。** Rust 实现核心与批处理 CLI；TypeScript strict、React 和 WXT 实现 Chrome 插件；TypeScript strict、React 和 Vite 实现网站。共享版本化契约和行为样例，按需共享界面组件；首版不引入 Rust WASM 或 Native Messaging。
3. **持久数据。** 插件 IndexedDB 按记录保存；私有仓库采用可检查、确定性排序的 JSON／JSONL 一致快照；公开数据为白名单投影后的紧凑 JSON 与 gzip。结构校验不能代替行为一致性验证，文本格式不能代替同步协议。
4. **身份与版本。** 收藏和标签使用独立稳定身份。记录需表达字段值、变更来源与版本、人工保护、明确拒绝的标签关联、删除状态及冲突候选。任务结果必须能关联到其输入和政策版本，迟到结果不得覆盖已变化的输入。
5. **网址契约。** HTTP(S) 绝对 URL 以完整 WHATWG 序列化结果去重，保留协议、片段、查询顺序、路径大小写及非根末尾斜杠等区别；统一协议／主机大小写、默认端口、空根路径和标准点段。同址保存返回已有条目；网址编辑冲突交给用户处理。不依重定向、canonical 或内容相似度合并。
6. **标签语义。** 平面标签，英文标准名与英文短定义统一概念，打标规则独立表达适用、排除与例子。按主题、用途和资源类型分类；实现语言留在 GitHub 元信息中。别名、旧名和译名指向同一标签。已有标签的改名、合并、删除和语义变更由用户操作。
7. **人工保护。** 每个标签关联和字段分别保护，人工拒绝不被 AI 恢复，手加关联不被 AI 删除。普通重跑不解锁，显式解除只作用于所选范围。缺失或未保护的自动内容仍可继续处理。
8. **多语言。** 首版 en 与 zh-CN；界面、标签显示名和定义可切换。译文保持英文原意；原文改变后更新未保护译文，保留人工译文并标记复核，缺失回退英文。
9. **同步契约。** 基于一致的共同基线和仓库版本做语义合并，写回包含一致数据与任务状态。不同字段可合并，同一内容的人工冲突保存双方。删除阻止迟到编辑自动复活；人工冲突和待发布变化可见。仓库写入竞争必须检测和重算，不能强推覆盖其他客户端。
10. **AI 政策。** 一个版本化来源覆盖所有实际生成任务：分类、命名、短定义、打标规则、显示名与定义翻译、必要说明文字。skill 与 API 装载同源政策。新增生成字段先补其政策；程序负责结构、引用、允许字段、输入版本和保护检查。
11. **AI 输入和返回边界。** 输入只含允许证据与所需标签信息，不含私人备注、凭据、浏览历史或 Cookie。正文可关闭，单条可跳过 AI。网页与 README 作为不可信数据；模型仅返回待验证结果，不获得整库替换或独立发布权限。缺失、空白、截断、无效或引用错误结果不得作为成功写入。
12. **AI 后端。** 本机使用 CLI 启动 codex exec 获取结构化结果；云端使用用户配置的 HTTP 服务。两条路径复用任务和验证规则；选择 Codex 后端才要求另装并登录 Codex。云端不自动访问用户电脑或复制本机登录文件。
13. **调度和增量。** AI 默认每 6 小时检查新增、缺失与待重试项；已有结果仅在相关输入／政策变化或显式要求时重算。GitHub 元信息每天检查、每仓库 7 天过期、每轮最多 500 仓库，按仓库去重并支持额度不足时续跑。插件触发前先同步，并区分请求已发出与任务已完成。
14. **错误和预算。** 认证失败／余额不足立即停止并挂起自动 AI，用户修复后恢复。限流、断连、超时与服务端错误每项在一次运行内最多尝试 3 次，含首次，遵守等待提示与任务、时限和费用上限。请求格式错误需修正；独立元信息与已有公开数据发布可继续，但整体状态不能掩盖 AI 失败。
15. **故障通知。** 首次未恢复故障在私有实例仓库创建 Issue 并提及配置的本人，重复失败不重复建 Issue、评论或提及，恢复关闭一次。启用 Issues 并授予工作流本仓库 Issues 写权限。只写脱敏故障类型、时间、建议和运行链接；不保证绕过用户通知设置强制送达。通知失败保留为独立错误。
16. **公开基础规则。** 三种模式：仅手动默认、任意包含标签后排除、全部减排除。空包含列表选中零条；反选模式必须主动启用。未设置公开性的标签中立。
17. **公开优先级。** 首先排除回收站；其次任意不公开标签一票否决；再排除手动私有；再接受手动公开；其余按基础模式。相同标签同时出现在包含和排除集合时排除生效。手动公开不能越过不公开标签。
18. **公开变化。** 配置保存前预览清单、数量、增删和原因。启用时明确标签变化会自动重算，包括新收藏与 AI 标签更新。标签改名保持规则身份；删除或合并规则引用时需检查范围变化。期望清单与上次成功部署分开表达，失败不标为已撤回。
19. **公开字段。** 只导出入选条目的 URL、标题、所用标签显示名与短定义、公开 GitHub 元信息，以及有效链接状态、简短原因和最近检查时间。备注、正文摘录、打标规则、AI 日志、回收站、冲突、完整私有标签库和密钥不进入公开数据。
20. **Pages 发布。** 私有任务导出白名单临时产物，显式触发公开仓库工作流；后者下载指定产物、组合站点并部署 Pages，然后清理公开产物。公开 Git 不提交收藏数据，不采用 amend 或 Release 存数据。跨仓库权限按 Actions 读／写用途配置；公开工作流无需私有源仓库 Contents 权限。临时产物清理、取消与失败路径需要验证，不承诺平台缓存或第三方副本可彻底回收。
21. **链接状态。** 未检查、可访问、检查受阻／待复查、持续不可访问。404/410 至少两次有效观测、间隔至少 24 小时后才自动判为持续不可访问；GitHub 404 不断言永久删除。受限、限流、网络与服务端错误保留受阻说明，归档、禁用、可见性及长期不更新独立显示。人工覆盖持续到明确解除。
22. **链接复查。** 每日调度，正常和失效默认每 7 天复查，首次 404/410 至少 24 小时后复核；普通网址每轮最多 500，可配置且支持立即复查。仓库主页复用元信息请求，深层链接单独检查。重定向只记录并提示，不改网址或合并。检查有超时、读取、重定向和速率上限，不携带浏览器 Cookie 或访问本机／私有网络；普通 HTTP 无法证明脚本状态或片段仍存在。
23. **失效展示。** 失效不删除、不取消公开、不清空已有内容。自动恢复只更新自动状态，人工覆盖保留。网站默认仍显示公开的失效条目，访客筛选仅改变视图，不改变公开清单。
24. **查询与批量操作。** 中英文关键词、标签与别名，AND／OR／NOT 和括号，GitHub 语言／星标／归档筛选，V2 查询分享链接；表达式不得经字符串执行。插件支持批量标签、公开选择和删除，公开网站保持只读。
25. **回收站与备份。** 删除可恢复、首版不自动清空，迟到编辑可保留待处理但不复活。整库备份包含完整 V2 数据、保护、删除、冲突与任务状态，不含密钥；恢复到新空实例，单条恢复在原实例完成。
26. **发行。** CLI 提供 Windows x64、Linux x64／WSL、macOS x64 与 arm64；Chrome 首版通过开发者模式加载发行包。安装、配置、权限、实际验证平台和最低系统要求随发行说明记录。
27. **样本验证与未定事项。** 20 条代表性收藏对照本机 Codex 与官方 DeepSeek Flash，DeepSeek 本次累计总预算 2 元且含重试，不切换昂贵模型。长期模型、自动 AI 批量和月预算依赖样本证据，当前不预设已获持续费用授权。

## Testing Decisions

测试依据用户可观察行为及数据输入输出，不测试私有函数调用顺序或为了覆盖率重复实现算法。V2 当前没有产品代码和既有测试边界；用户已确认以下四组边界，已有设计中的行为样例和验收约束继续有效。

| 边界 | 如何验证 | 主要覆盖 |
| --- | --- | --- |
| 核心公开操作／CLI 与持久快照 | 通过真实入口输入收藏、政策及修改，读取最终状态、公开导出和退出结果；共享样例在 Rust 与 TypeScript 两端核对 | URL 身份、人工保护、公开否决、增量任务、回收站与恢复 |
| 两个独立客户端与仓库同步边界 | 两端从共同基线离线编辑，对可控的仓库 API 执行交错同步、版本竞争及重试，检查最终数据与冲突呈现 | 不同字段合并、同字段人工冲突、删除与迟到编辑、旧 AI 结果 |
| 外部服务边界 | 用可控 HTTP 响应、子进程结果和时钟模拟模型／GitHub／网页状态，不模拟被测模块内部实现；真实服务仅做独立集成验收 | 结构错误、限流、预算、挂起恢复、Issue 去重、链接复查 |
| 浏览器与发布边界 | 使用实际构建的插件和网站完成关键用户路径；对导出与真实 Pages 部署分别验证，不用页面隐藏代替数据隔离 | 收藏编辑、双语、查询、规则预览、发布撤回、失效筛选、清理产物后仍可访问 |

必须覆盖的行为包括：

1. 完整 URL 规范化的等价与不等价样例；重复收藏保留人工内容，网址修改冲突不静默合并。
2. 包含标签与不公开标签同时命中时不得公开，即使手动公开；中立标签、空包含列表、反选、回收站和同标签双列表的结果正确。
3. 修改规则与 AI 标签变化能得到可解释的公开清单；期望状态、同步状态及实际成功部署状态不混淆。
4. 手工添加／拒绝标签、逐字段保护、普通重跑、选择性解除及原文变化后的人工译文。
5. 两客户端不同字段及同字段修改；写回版本竞争；删除与迟到编辑；任务计算期间输入发生变化。
6. 无效、空白、截断或越权的 AI 输出不能落库；恶意页面文字不能改写权限、指挥工具或扩大公开输出。
7. 401/402 立即挂起并要求手动恢复；临时故障最多三次尝试；成功子结果和续跑位置保留；全部重试计入预算；必要失败导致非零退出而非成功摘要。
8. 同一未恢复故障首次通知一次、重复失败不重复提及、恢复关闭；通知失败不覆盖原始错误，内容不暴露密钥或私有输入。
9. 单次 404 不直接判失效，间隔不足不累计为确认；GitHub 私有化与归档不被错误描述；深层链接独立检查；人工状态不被自动覆盖；失效恢复不自动改变公开选择。
10. 公开投影不含私有字段与未入选条目，公开 Git 无收藏数据，取消公开下一次成功部署移除；部署后删除临时产物仍能读取网站与数据，失败或取消可清理。
11. 双语关键词／译名／别名、布尔表达式、GitHub 筛选、分享链接、批量操作及失效过滤；字符串表达式不作为代码执行。
12. 备份恢复到新空实例后语义一致，包含保护、删除、冲突和任务进度而无密钥；四种 CLI 目标与插件包的安装运行检查。

真实模型验收使用既定 20 条样本及 2 元总预算，报告分类、定义、译文质量、耗时和用量；故障注入测试不消费真实模型预算。没有凭据或目标平台环境时保留待执行状态，不将模拟验证称为真实集成通过。当前没有可复用的 V2 测试实现；V1 仅提供调查背景，不要求继承其接口或测试结构。

## Out of Scope

- 团队协作、集中账号或托管的多租户服务。
- 首版 V1 数据导入、旧 Python CLI／API 兼容、旧分享链接兼容；旧数据与百科长说明留在原项目。
- 手机录入、普通网站编辑、Chrome 商店上架及默认承诺代码签名。
- 标签父子层级；AI 擅自修改已有标签语义、改名、合并或删除。
- AI 摘要、改写用户备注、生成页面标题等尚未确认的内容功能。
- Rust WASM、Native Messaging、本机常驻 HTTP 服务及云端访问个人电脑上的 Codex 登录态。
- 自定义二进制数据格式、浏览器 SQLite、预先引入分片或后台解析 Worker；性能问题根据测量再处理。
- 自动删除失效收藏、自动取消其公开、自动改写重定向 URL 或合并条目、自动清空回收站。
- 全站爬虫、携带登录 Cookie 的链接巡检或自动保证脚本页面内容仍存在。
- 把私有数据放入公开 Git、通过 amend 发布收藏数据、将隐藏 UI 当成隐私隔离。
- 保证清除平台所有缓存或第三方保存的公开副本。
- 将本次 2 元调试预算视为持续任务预算，或在样本完成前擅自确定长期付费模型和月预算。
